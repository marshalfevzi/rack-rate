## Scope

**Migrate the social card from Satori to Takumi.**
**Files:** `apps/site/scripts/og.ts`; `apps/site/package.json` and `bun.lock`;
the two Satori faces `apps/site/src/assets/fonts/ibm-plex-sans-latin-{400,600}-normal.woff`;
the `## Social card` section of `ARCHITECTURE.md`.
**Work:** replace the two-package pipeline — `satori` 0.33.4 turning the element
tree into SVG and `@resvg/resvg-js` 2.6.2 rasterising it — with one package:
`takumi-js`, pinned exactly at 2.14.0 (MIT OR Apache-2.0), whose `render()` takes
the card tree plus `{ width, height, fonts }` and returns encoded PNG bytes. Both
old packages leave `apps/site/package.json` and `bun.lock`; the
`satori/jsx/jsx-runtime` import goes with them, since it existed only to work
around satori's TS2345 on variadic children. The card tree itself survives: audit
every container for an explicit `display: flex`, because satori defaulted `div`
to flex and Takumi defaults it to block.

**Keep what the section already promises.** The 1200×630 size contract with its
PNG magic-byte and IHDR width/height assertion, the fail-closed check that
`apps/site/dist/index.html` exists, the palette read at build time from the
`@theme` block in `apps/site/src/styles/global.css` (a renamed or missing
`--color-canvas`, `--color-ink`, `--color-dim` or `--color-rule` still fails the
build with the token named), the content rule — wordmark, the two questions, the
counts read through `apps/site/src/lib/data.ts`, the origin from the built
page's canonical link, and deliberately no score, cost, quota or confidence
figure — and the post-build position in the root `bun run build` sequence.

**Fonts.** Takumi reads WOFF2, WOFF and TTF directly and synthesises bold and
oblique through `font-synthesis`, so the card registers the five committed latin
WOFF2 faces under `apps/site/src/assets/fonts/` that UI-502 already ships to the
browser, passes them as buffers read from disk, and maps the card's
`fontWeight: 700` onto the frozen 600 step as before. The two `.woff` faces
committed only because satori cannot read WOFF2 and cannot synthesise weight are
deleted, with nothing left referencing them. No `googleFonts()`, no `fontFromUrl()`
and no bare-URL font entry: every face is a committed file, so the build stays
offline (invariant 9). Prove the faces are the ones used rather than a fallback —
Takumi falls back to a built-in Geist rather than failing — by asserting through
`renderSvg()` that the resolved families are the Plex families, or by an
equivalent measured check that fails when a registered face is dropped.

**Measure, do not carry over.** Takumi never reads system fonts, so the
`loadSystemFonts: false` knob has no counterpart and disappears. Takumi's docs
promise no byte-identical output, so determinism is re-established here: two
consecutive `bun run build` runs must write a byte-identical `dist/og.png`, and
its sha256, byte length and dimensions are recorded in `ARCHITECTURE.md` in place
of the satori-era `23677cc0…` / 45,413 bytes. The `@takumi-rs/*` platform
bindings are optional dependencies, so `bun install --frozen-lockfile` needs no
Rust toolchain on this workstation or in CI; say so in the section.

**Done when** `bun run build` writes `dist/og.png` at 1200×630 through
`takumi-js` alone; `satori` and `@resvg/resvg-js` appear in neither
`apps/site/package.json` nor `bun.lock` nor the installed tree; a build with the
network unreachable still writes the card; two consecutive builds are
byte-identical; `renderSvg()` of the same tree names the Plex families and no
fallback family; the two `.woff` faces are gone from the tree with exactly five
committed faces under `apps/site/src/assets/fonts/`; and `ARCHITECTURE.md`'s
`## Social card` section describes the shipped pipeline with its licence, its
measured hash and its size, with no sentence left over from the satori and resvg
pair.

## Notes

Created on 2026-09-17 at the owner's request, after UI-502 moved the fonts to the
Astro Fonts API; `DEC-2026-09-17-008` records why this stage carries it and why
the engine changes at all. The upstream project is
[takumi](https://github.com/kane50613/takumi) (`takumi-js` on npm); its own
migration guide for satori is
[takumi.kane.tw/docs/comparison-to-satori](https://takumi.kane.tw/docs/comparison-to-satori).

The engine swap is upstream-verified but not yet locally measured: `takumi-js`
2.14.0 is MIT OR Apache-2.0, ships native prebuilts for darwin-arm64 and
linux-x64-gnu plus a browser WASM build, loads no font provider unless asked, and
documents WOFF2 support, while its byte-determinism is undocumented and its
WOFF1 handling is inferred rather than stated. Everything this task asserts about
the card is therefore asserted from a build, not from the guide.
