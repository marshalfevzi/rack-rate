## Scope

**Shareable static image of a filtered chart view.** **Files:** new `apps/site/src/lib/share/card.ts`, new `apps/site/src/lib/share/render.ts` and `apps/site/src/lib/share/card.test.ts`; `apps/site/src/pages/explore.astro` and the plate section components `apps/site/src/components/{HeatmapSection,RadarSection,SlopeSection,WaterfallSection}.astro` plus the Pareto and bump plates; `apps/site/src/components/ControlRow.astro`; `ARCHITECTURE.md`, `docs/design/surfaces.md`, `PRD.md` and the Capabilities section of `PRODUCT.md`. **Work:** a reader on `/explore` can turn the view they are actually looking at into one static image they can keep or share. The cards are drawn by `takumi-js`'s WASM build in the reader's own browser, because the site is static with no server and no adapter: an arbitrary filter state cannot be rendered into a fetchable URL, so the image can only be produced where that state exists.

**The card is a pure function of the view.** `card.ts` takes the plate's payload from the same `apps/site/src/lib/charts/*-payload.ts` module the mounted chart consumes, the parameter values in force (the plate's URL state: metric, chart type, vendor, effort, score floor, axis scale, frontier, composite weights), the readout line from `apps/site/src/lib/readout.ts`, and the token values, and returns the card's markup and its file name. It reads no clock, no random value and no network: the same URL state produces the same markup, the same bytes and the same name, `rack-rate-<route>-<filter-hash>.png`. Token values are read from the document the way `apps/site/src/lib/charts/theme.ts` already reads them, and are interpolated as literals, since the renderer sees no stylesheet from this page.

**The composition is the Console Listing grammar, at 1200×630.** Square corners, 1px `--color-rule` rules, `--text-micro` uppercase mono legends, the plate's title with its basis named in words, the figure drawn from the payload, the parameter values in force, and the view's headline values printed in the readout's fixed order `VALUE · BASIS · CONFIDENCE · SOURCE · RETRIEVED` — a missing value prints `—` with its `known_gaps` reason beside it. Only the frozen ten tokens appear; no second hue, radius, shadow, gradient or duration; and no figure appears that the page itself does not publish, so the image cannot become the only place a contractual fact exists.

**Rendering is opt-in per activation.** `render.ts` imports `takumi-js` dynamically, fetches only the emitted Plex WOFF2 faces from the site's own hashed font output, passes them as buffers, renders 1200×630 PNG bytes and hands the reader the file. No `googleFonts()`, no `fontFromUrl()`, no bare-URL font entry, no `.json` or API request: the card is built from state the page already holds, so the export works with the same offline guarantee the rest of the build has.

**The control belongs to the control row.** Each of the six plates gains a `SHARE IMAGE` text control in its own control row — never floating chrome, and never inside the chart canvas. It is keyboard-operable with `Enter` and `Space`, announces idle, busy, done and error states through `aria-live`, draws those states as text on the frozen tokens (no spinner and no shimmer, which this stage bans), and is disabled with a stated reason when the view has no rows. It is never the ECharts toolbox's `saveAsImage`: the toolbox stays banned and unregistered, and `DESIGN.md` already puts zoom, filtering, axis and export in the labelled control row. The page's twin tables remain the JavaScript-free path, so without scripting the action is absent rather than broken, and no contractual fact exists only in the image.

**The export is bound by the Artificial Analysis rules.** `CAVEATS.md` §1.5 and task `DOC-702b` state that in the chart-only state no AA value enters `data/*.json`, any export, any table or any CSV. The card is therefore PNG and nothing else: never `renderSvg()`, never a CSV or JSON sidecar, because an SVG or a data file would reproduce AA values in the structured, machine-readable form §2.3(c) and §2.4(b) rule out. When the build is in the chart-only state, the AA axis appears on the card only as its own labelled axis with the AA logo and source line baked into the pixels — an image cannot carry the page's hyperlink, so both are part of the frame, per §5.1's chart row. No AA value appears in the card's listing or readout block. This task creates no AA value and changes no publication gate: with `AA_PUBLISH=0` there is no AA axis to render and the card's composition is unchanged, and in `AA_PUBLISH=1` the card carries exactly what the page already publishes.

**Every figure travels with its record.** `ARCHITECTURE.md`'s card rule refuses a figure in an image because an image carries no basis or confidence badge, and invariants 4 and 5 require both of a published number. This card satisfies that rule rather than excepting itself: every figure is baked with its basis, confidence, source and `retrieved` date, and every benchmark value with its `benchmark_version`, so the image reads as one console record and loses nothing when it leaves the page.

**Not in this task:** `/compare` and `/models/[slug]` keep their plates without an export, no OG image is generated per route, nothing is uploaded anywhere, no clipboard action is added, and no preference is persisted. **Done when** on a built preview (`bun run build` then `bun run preview`) at 1440px, 768px and 360px, each of the six `/explore` plates exports a 1200×630 PNG by keyboard alone; every figure on the card equals the value the page publishes for the same URL state, and the drift test fails when a card figure changes while its payload does not; every figure carries its basis, confidence, source and retrieval date; exporting issues no request beyond the same-origin font files and the dynamically imported renderer chunk; a route outside `/explore` ships neither the renderer chunk nor the WASM module; the same URL state twice yields the same file name and byte-identical image; the export produces a PNG and nothing else — no SVG, no CSV, no JSON sidecar is emitted or offered — and in the chart-only Artificial Analysis state the card carries the AA logo and source line with no AA value in its listing block; with scripting disabled the control is absent, not broken, and the twin tables still carry every value; and nothing is written into `dist/` or committed.

## Notes

Created on 2026-09-17 at the owner's request; `DEC-2026-09-17-008` records the placement and why this stage carries it. It is ordered last in the milestone because it renders through the engine `APP-516` installs, and because it draws the grammar `UI-509` themes and the plates `UI-511` leaves with real control rows.

The card deliberately reuses the payload builders and the readout contract rather than drawing the figure a second way: an image that re-derived its own numbers could drift from the page silently, which is the failure mode a shareable artifact must not have.
