## Scope

**Self-hosted IBM Plex, its licence, and the two generated assets.**
**Files:** the five latin-subset woff2 faces
`apps/site/src/assets/fonts/ibm-plex-sans-latin-{400,500,600}-normal.woff2` and
`apps/site/src/assets/fonts/ibm-plex-mono-latin-{400,500}-normal.woff2`, the two
Satori faces `apps/site/src/assets/fonts/ibm-plex-sans-latin-{400,600}-normal.woff`,
and `apps/site/src/assets/fonts/LICENSE.txt`; `apps/site/astro.config.mjs` (the
`fonts` block); `apps/site/src/layouts/Base.astro` (`<Font />` in the head);
`apps/site/src/styles/global.css` (`--font-sans` / `--font-mono`);
`apps/site/scripts/og.ts`; `apps/site/public/favicon.svg`; delete
`apps/site/assets/fonts/**` only once nothing references it.
**Work:** acquire the seven faces once from the `@fontsource` jsDelivr file paths
(`@fontsource/ibm-plex-sans@5.3.0` and the matching `ibm-plex-mono`), commit them
with the IBM Plex OFL 1.1 text, and record each file's source URL, byte length and
sha256 in `ARCHITECTURE.md` so the committed bytes stay verifiable. Register both
families in the Astro Fonts API — `fontProviders.local()` over the committed woff2,
`formats: ["woff2"]`, `cssVariable: "--font-plex-sans"` and `"--font-plex-mono"`,
real fallbacks — and include `<Font />` for each family in the `Base.astro` head, so
Astro generates the `@font-face` rules, the preload links and the metric-matched
fallbacks instead of hand-written CSS. Point `--font-sans` and `--font-mono` in the
`@theme` block at the Astro variables; keep prose in Sans and figures in Mono. No
remote font provider: the build keeps working offline (invariant 9). Move `og.ts`
off Lato onto Plex Sans 400 and 600, read from the two committed `.woff` faces
because Satori reads TTF, OTF and WOFF but never WOFF2, and map the card's
`fontWeight: 700` onto the frozen 600 step; its palette reader keeps following
`@theme`. Update the two media-scoped `theme-color` values to the frozen canvas
values. The favicon keeps its 32×32 SVG geometry and is judged at the 16px a
browser tab actually renders, not at an authored size: if the 1.5px rule weights
close up at that size, adjust the rule weights only — the geometry, the gutter and
the single amber signal stay as they are.
**Done when** the browser loads only the woff2 emitted by the Astro font pipeline
(hashed under `_astro/fonts/`) with zero remote font requests and no build step
reaches the network, every committed face's sha256 and byte length matches its
recorded value, computed styles report Plex Sans for prose and Plex Mono for data,
the favicon reads at 16px, `dist/og.png` is 1200×630 in the console palette, and no
Lato family or path remains anywhere in the tree.

## Session

Self-hosted IBM Plex, its licence, and the two generated assets.

Landed: five latin-subset woff2 faces and the two Satori woff faces plus LICENSE.txt under apps/site/src/assets/fonts/, registered through the Astro Fonts API (fontProviders.local) in apps/site/astro.config.mjs and preloaded by <Font /> in Base.astro; global.css binds --font-sans/--font-mono to the two Astro font variables and binds figures to Plex Mono through the existing .tabular carrier; apps/site/scripts/og.ts and apps/site/public/favicon.svg now draw the committed local faces; the vendored apps/site/assets/fonts/** Lato tree is deleted and referenced by nothing.

Evidence: a clean build emits exactly five dist/_astro/fonts/*.woff2 (no woff/ttf/otf anywhere in dist) with 5 preloads and 10 @font-face rules on all built pages and zero foreign-origin requests on 11 routes x 2 widths; all seven faces are byte-identical to their recorded jsDelivr upstream paths and all eight committed files match the ARCHITECTURE provenance table 8/8 by sha256 and byte length; LICENSE.txt is the two upstream notices plus one shared OFL body. Chrome CSS.getPlatformFontsForNode paints IBMPlexSans-Regular for prose, IBMPlexSans-SemiBold for h1 and IBMPlexMono-Regular/IBMPlexMono-Medium for every .tabular figure on /, /models/, /plans/, /plans/claude-max-20x/, /models/claude-opus-5/, /compare/ and /method/, in both schemes. dist/og.png is 1200x630 within the frozen palette (58 unique colours, all on canvas->token rays, zero amber); favicon.svg is byte-identical to HEAD, unchanged, and legible at 16px; no live Lato family or path remains; scrollWidth equals clientWidth on 11 routes at 1440px and 360px.

Two defects found by independent verification and repaired in session. (1) The .tabular figure carrier named no family, so the clause "computed styles report Plex Mono for data" was false for every figure on every route; fixed by adding font-family: var(--font-mono) to the .tabular rule in global.css, with a counterfactual reproduction of the pre-fix failure. (2) That binding then put prose in monospace - the break-even cell renders the sentence "Never breaks even at list rates" and the "—" placeholder, which M5's stage contract bans; fixed by giving budgetDisplay in index.astro a breakEvenIsFigure field and binding the cell's class to it, so only numeric values carry .tabular while the prose and placeholder values stay Plex Sans. The client bundle needed no change: the state is build-time-fixed and invariant under the task-count input. ARCHITECTURE.md Stage-5 records were corrected to measured facts: the face column is a DESIGN.md role rather than a per-step call site, --text-micro/--text-data remain unconsumed and pruned, the platform-font names are the response's postScriptName field, and the --color-faint pruning claim is scoped to the emitted @layer theme block.

Gates: bun run check exit 0 (typecheck, oxlint, Markdown lint, oxfmt clean, astro check 0 errors/0 warnings/0 hints), bun test exit 0 (153 pass, 0 fail), bun run data:check exit 0 with data/derived.json unchanged, bun run build exit 0 from a clean dist with dist/og.png 1200x630 / 44,364 bytes.

Known gap recorded, not this task's clause: the five prescribed latin subsets lack U+2192 "->" and U+03A3 "Σ", so those glyphs paint in the declared metric-matched faces - the arrow once on /start/ and the sigma twice in the formula on /method/. A non-ASCII leaf sweep of 166 elements over 11 routes found no other case. Resolving it needs either additional unicode-range subsets or a copy change, and is a Stage 5 follow-up decision.
