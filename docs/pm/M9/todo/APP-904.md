## Scope

**Flatten the frontend into a component tree a stranger can read.** The measured starting point is concrete: `apps/site/src/pages/compare.astro` is 711 lines and carries its own table engine, its own sort logic and its own payload assembly; `apps/site/src/lib/console-data.ts` is 514 lines and `apps/site/src/lib/console-client.ts` is 394 with overlapping responsibilities; `apps/site/src/pages/explore.astro` is 367; `apps/site/src/pages/method.astro` is 386; `apps/site/src/pages/models/index.astro` is 326. The same chart-plate markup is repeated six times across four section components and two routes, `Chip.astro` and `CostBasisChip.astro` carry the same style twice, and the plan helpers are duplicated between `plans/index.astro` and `plans/[slug].astro`.

**Files:** `apps/site/src/pages/` (all eleven routes); `apps/site/src/components/` (the section and primitive set); `apps/site/src/lib/` (the data, payload and client modules the routes currently assemble inline); `docs/design/components.md` (new — the component inventory); `ARCHITECTURE.md`'s site section.

**Work:** define one composition convention and write it down, then make every route obey it. A route page reads as a short composition: it resolves its data through a module, then renders named sections, and it contains no table engine, no sort implementation, no filter-row markup, no chart-plate markup, no inline `<style>` block and no page-local data assembly. Each repeated idiom becomes one component with one owner: the listing table with its head, gutter and state cell; the sortable head; the filter and control row; the chart plate with its control row and its table twin; the metric matrix; the detail row set; the section head with numbering; the page header with its answer line.

**Duplication is deleted, not tolerated.** Where two components implement the same thing, one survives and the other's callers migrate in the same change. Where a shared module and a route compute the same payload, the module wins and the route's copy is removed.

**The deliverable includes the map.** `docs/design/components.md` lists every component, its one responsibility, the routes that compose it, and the convention a new component must follow — so the next contributor adds to the tree instead of to a page.

## Done when

- Every route under `apps/site/src/pages/` meets the convention: no table engine, no sort implementation, no filter-row markup, no chart-plate markup, no inline `<style>` and no page-local payload assembly.
- No duplicated implementation remains: one table, one sortable head, one filter row, one chart plate with its twin, one basis chip, one set of plan helpers.
- `docs/design/components.md` exists, matches the tree on disk, and states the convention.
- Every route still renders the same information it did before the restructure — same figures, same basis, same confidence, same sources, same gaps — from a built preview, in both schemes, at 1440px, 768px and 360px.
- `ARCHITECTURE.md`'s site section describes the shipped structure.
