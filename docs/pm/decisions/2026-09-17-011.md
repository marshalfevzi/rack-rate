# The fixed tracks below 768px come from the table's own columns, not from the hidden header row

## Context

The second re-verification of UI-506 returned `fix` on 2026-09-18 and the task's own `## Session` section records that failure as a blocker, because the task had consumed its single allowed fix round. Nothing in the plan carries that: `docs/pm/M5/todo/UI-506.md` still reads `status: todo` with `blocked_by: null`, so `/pm` selects UI-506 as the first runnable task on every run and repeats the same implement, verify, fix, fail cycle.

The failing criteria are geometric and were measured on a rebuilt preview at 360, 390, 480, 600, 768 and 1440 in both schemes. The readout listing's state cell measured 62.390625px at 360, 68.390625px at 390, 72px at 480 and 92px at 600 against a required 20px, and its line-number gutter measured 72px at 480 and 92px at 600 against a required 28px. The same cells measured exactly at 768px and 1440px, and the row tracks and the `scrollWidth === clientWidth` criterion at 360px passed.

Those four numbers are an identity rather than noise: 62.390625 = 312/5, 68.390625 = 342/5, 72 = 432/6 and 92 = 552/6, where 312, 342, 432 and 552 are the table's content width at those viewports and 5 and 6 are the column count below and above the 480px gutter breakpoint. Below 768px the columns are therefore divided equally across the table's width: no pinned width is applied at all, in either table.

The unlayered console block in `apps/site/src/styles/global.css` pins every track through `tr > :nth-child(n)` selectors and relies on `table-layout: fixed` to read those tracks from the table's first row. Inside `@media (max-width: 767px)` it also sets `.console-table thead { position: absolute; width: 1px; height: 1px }` and `.console-table thead tr, .console-table thead th { display: block; width: 1px }`. The `display: block` takes the header row's boxes out of the table's internal structure, so at those widths the fixed layout has no first row to take tracks from and falls back to equal division, which is the measured signature. It is also the only rule that differs across the 767px boundary and can void the first row. At 768px and above the header row keeps its table display, the first row supplies the tracks, and every pin holds exactly. Both fix rounds to date changed widths and left the header row's `display` in place, so both left the pins inert below 768px.

The frozen geometry itself is satisfiable: at 360px the readout's pinned columns (20px state cell, 88px model, 56px and 56px numerics) leave 92px of the 312px content width to the flexible Plan column, and at 480px they leave room for the 28px gutter as well. No acceptance criterion has to be withdrawn.

## Decision

a. A table's tracks are anchored to the table, not to its first row. The accepted mechanism is a `<colgroup>` with one `<col>` per column carrying the pinned width and exactly one `<col>` left flexible — the readout listing's Plan column, and the label column of the two index tables — so the used width equals the specified width at every viewport of the DEC-2026-09-17-009 matrix (360, 390, 480, 600, 768 and 1440, both schemes). Keeping the header row in normal flow with `table-header-group`, `table-row` and `table-cell` display and hiding it visually without changing `display` is equally acceptable. Pinning through cell-level widths alone stays withdrawn: DEC-2026-09-17-010 clause (b) measured it as content-derived, and this record adds that a cell-level mechanism is also voided whenever the row it targets is not a table row.

b. This record authorizes the markup change carried by the two earlier records: `apps/site/src/components/ConsoleListing.astro` and `apps/site/src/components/ProvenanceIndexTable.astro` may carry a `<colgroup>`, and `apps/site/src/styles/global.css` may move the track widths into it. It also states the constraint that makes a colgroup the first choice: `apps/site/src/lib/console-client.ts` clones the readout listing's rows from `<template id="console-row-template">`, and a cloned row carries no width, so the tracks must live on the table itself and never only on the rendered rows.

c. The geometry criteria of DEC-2026-09-17-009 and DEC-2026-09-17-010 stand unchanged: the 20px state cell is never dropped, the line-number gutter is 40px at 768px and above, 28px at 480-767px and absent below 480px, numeric columns have a 72px minimum at 768px and above, all four readout fields are present below 768px, `document.documentElement.scrollWidth === document.documentElement.clientWidth` holds at 360px, and listing rows measure exactly 36px at 768px and above and exactly 44px below. No criterion is withdrawn: the equal-division arithmetic shows the pins never ran below 768px, so the phone-width failures are a mechanism defect and not an unsatisfiable requirement.

d. UI-506 has consumed its single allowed fix round, so this record authorizes one further implementation pass and one verification pass for UI-506. A second fix round is not granted in advance; a failure of that pass is a new blocker and requires a new decision.

e. The pass must measure rather than reason. Before it reports, it captures the used width of the state cell, the gutter and each numeric column at 360, 390, 480, 600, 768 and 1440 in both schemes from a rebuilt preview (`bun run build` then `bun run preview`), never from `astro dev`, as the milestone's reporting rule already requires. A claim about a track that no capture shows is not evidence.

f. Nothing else moves. No token, hue, radius or duration is added; `DESIGN.md` is unchanged; no data file, package, route, URL meaning, element id, `data-*` hook or copy string changes; the eleven-route set and the stage's boundaries in `docs/pm/M5/README.md` hold. The Console Listing world stays DESIGN.md's, and a change to the world itself is a design decision, not part of UI-506.

g. The already-passing criteria of the last re-verification are retained and must not regress: the no-query default rendering Claude Pro, claude-opus-4.8 and 300 tasks; the `plan`, `models` and `tasks` URL round-trip; the five former insight statements as rows; no `.json` or `/api` request from the browser; the 390px greyscale capture keeping every state, basis and confidence distinction; the 2px head rule, the sticky head at 32px and the frozen ten tokens; and the empty state for `models=not-a-model`, an explicit `models=` and an all-cleared selection, each rendering zero rows with `No rows match the current filters.` and leaving the URL unrewritten.
