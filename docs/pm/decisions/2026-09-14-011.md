# The chart platform boundary: pure builders, one `use()` call, series registration checked at mount time

## Context

`apps/site/src/lib/charts/` holds the platform: `registry.ts` (the repository's only `echarts.use()` call), `theme.ts` (the `@theme` token reader and one accent per cost basis), `frame.ts` (the shared cartesian frame and the series marker), `mount.ts` (the mount helper), and `frame.test.ts` / `theme.test.ts` for the pure halves. Builders stay pure — `(data) => ChartOption`, no `use()`, no DOM, no clock — and `mount.ts` is the only module in the directory that touches `window`.

## Decision

The sentence the 4.1 entry originally carried — that an option object therefore cannot carry a series type no stage registered, and a missing `use()` is a type error rather than a blank chart — is false and is superseded by "Second review finding" and "Third review finding"; the option type accepts any extra key, and the registry checks series names at mount time instead.

It is now guarded with public data only. `registry.ts` holds `SERIES_INSTALLS`, one row per family pairing the install object `use()` receives with the `series[].type` string an option must use, and `use()` is fed from those rows — so registering a family and teaching the guard its name are the same edit — and `unregisteredSeriesTypes(option)` compares an option's declared types against them. `mount.ts` calls it before `setOption` and throws `the option declares the unregistered series type scatter: add it to SERIES_INSTALLS in src/lib/charts/registry.ts`; the refused mount disposes its instance, so a retry reports the real problem instead of "already holds a chart instance". `registry.test.ts` covers the pure half in five cases (a missing type named once for two series, no series at all, a series with no `type` field, a single series object rather than an array), and the table starts empty, so the guard rejects every named family until 4.2 adds the scatter row.

## Consequences

- A missing `use()` is caught at mount time, not by the option type: the `SERIES_INSTALLS` guard rejects an option whose declared series family has no registered row, and the refused mount disposes its instance so a retry reports the real problem.
- The 2026-09-17 plan review added the obligation to unit-test the five builders that were only ever verified by rendering. That obligation is `UI-509` in `docs/pm/M5/` (`docs/pm/M5/README.md`, `docs/pm/M5/todo/UI-509.md`).
