# Terminal-Bench token mapping: `tokens_input` is `uncached_input_tokens`, asserted per row

## Context

Upstream's `metrics.total_tokens` equals `metrics.uncached_input_tokens + output_tokens` **exactly** on all 18 display rows, so cached reads are already inside `uncached_input_tokens` and the sum this repo published (`cached + uncached`) was 1.87–1.95× the true input — e.g. `gpt-6-astra` shipped `2,949,141,032` instead of `1,505,789,330`.

## Decision

`tokens_input` is `uncached_input_tokens`. The identity is asserted per row and fails the run if it breaks, and `cached_input_tokens`, `uncached_input_tokens`, `total_tokens` plus a `token_mapping` note are kept in the row provenance so the mapping is auditable.

## Consequences

- The identity is asserted per row and the mapping is auditable in row provenance.
- This was the one wrong number in committed data, and a 1.9× error is worse than a missing one.
