# One root `tsconfig.json` with no project references

## Context

Task 1.2 had to decide and record one of two shapes for the three packages: a single root `tsconfig.json` or project references into the packages. The `Stage 1 executed` session recorded the choice as **Strategy C**, with this rationale: "A referenced project requires `composite: true`, which cannot coexist with the root's no-emit typecheck (`TS6310: Referenced project '…' may not disable emit`). An `include` with no matching file is also a hard error (`TS18003: No inputs were found in config file`), so 1.2 and 1.3 landed in the same wave."

## Decision

One root `tsconfig.json`, with no project references. `apps/site/tsconfig.json` extends the root, and `lib: ["ES2023","DOM"]` is deliberate and blanket.

## Consequences

Because the root typecheck is no-emit, `composite: true` cannot coexist with it (`TS6310`), which is what rules out project references. An `include` with no matching file is a hard error (`TS18003`), so task 1.2 could not land without task 1.3; the two landed in the same wave.
