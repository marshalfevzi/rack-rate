# M5 carries two image follow-ups: the Satori → Takumi swap and a shareable chart card

## Context

M5's stage record states two boundaries that its own queue cannot satisfy while staying useful. It bans a new dependency outright, and it confines `apps/site/scripts/og.ts` to what task UI-502 prescribes. Both sentences were written when the social card's engine was settled and the chart surfaces had no export.

Two facts have moved. UI-502 registers IBM Plex through the Astro Fonts API and commits seven faces, five WOFF2 for the browser plus two WOFF for the card, because `satori` 0.33.4 rejects WOFF2 and synthesises no bold — the second constraint is why a 600 face exists for a card that asks for 700. And the upstream engine now offers a single-package replacement: `takumi-js` 2.14.0 (MIT OR Apache-2.0) turns a JSX tree, an HTML string or a node tree into encoded PNG bytes, replacing both `satori` 0.33.4 and `@resvg/resvg-js` 2.6.2; it reads WOFF2, WOFF and TTF, synthesises bold and oblique through `font-synthesis`, never reads system fonts, ships native prebuilts for darwin-arm64 and linux-x64-gnu plus a WASM build for browsers, loads no network font provider unless one is asked for, and documents the satori migration directly.

The owner asked on 2026-09-17 for the renderer migration to be registered as a task, for a second task that exports a static shareable image of a filtered chart, for both to be ordered in the queue, and for every other affected task to be named. Asked to place them, the owner chose **after UI-515** — the stage's existing queue keeps its shape and the two follow-ups close it — and chose a **purpose-built card rendered by Takumi** over exporting the mounted chart.

A third constraint decides the second task's shape: the site is static with no server and no adapter, so an arbitrary filter state cannot be turned into a fetchable URL. A shareable image can only be produced where the filter state exists — in the reader's browser, from data already shipped.

## Decision

M5's boundaries are amended for exactly two tasks, appended after UI-515, and for nothing else:

- **APP-516** swaps the social card's engine to `takumi-js` 2.14.0 and deletes `satori` and `@resvg/resvg-js`. The dependency delta is two removed, one added. The card keeps its 1200×630 contract, its palette read from the `@theme` block, its fail-closed `dist/index.html` guard, its PNG magic-byte and IHDR assertion, its content rule and its offline determinism; it reads the five committed latin WOFF2 faces and the two WOFF faces committed only for satori are deleted, so the stage ends with exactly the five faces its acceptance line already claims.
- **UI-517** adds a `SHARE IMAGE` action to the six `/explore` chart plates' control rows and renders a 1200×630 card from the filtered view with Takumi's WASM build in the reader's browser, dynamically imported so no route without a plate carries the runtime. The card's figures come from the same payload builders and the same readout contract the page uses, so no number is authored twice and no fact exists only in the image.

Both remain inside every other M5 boundary: no server endpoint, no client-side data request, no route, slug or URL meaning change, no second hue, radius, shadow, gradient or duration, and the frozen ten tokens only. The `data/derived.json` hash pin stands untouched — neither task reads or writes published data.

## Consequences

The stage's ordered queue grows from fifteen tasks to seventeen, and the two new ones are the only tasks whose `pre` fields are non-empty: ordering alone would have hidden their coupling. `APP-516` depends on `UI-502`; `UI-517` depends on `UI-504`, `UI-505`, `UI-509`, `UI-511` and `APP-516`, which is what makes the appended order checkable rather than asserted.

`ARCHITECTURE.md`'s "Social card" section is the document APP-516 rewrites: the two-package sentence, the MPL-2.0 footnote, the satori-bold rationale, the `loadSystemFonts` paragraph, the `satori/jsx` TS2345 trap and the recorded sha256 all describe a pipeline that no longer exists, and Takumi documents no byte-determinism guarantee, so the card's hash is re-measured rather than carried over. UI-514's reconciliation of the social card and UI-515's re-derivation of the design record both land before APP-516 and stay correct for everything except that section, which APP-516 owns afterwards.

`UI-517` is the first surface in this project to ship a rendering engine to the browser. It narrows that exposure deliberately: the WASM runtime loads only from a chart plate's control row, only on activation, and only the emitted Plex WOFF2 faces are fetched — same-origin static assets, never a data request. The export is a reader artifact: it is written nowhere in `dist/` and committed nowhere.

A later stage that needs another card weight adds a variant to the `fonts` config or a face to the card's font list, not a rule in CSS.
