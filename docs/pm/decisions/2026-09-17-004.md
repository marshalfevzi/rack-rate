# PLAN.md and docs/architecture.md are superseded by the PM document tree

## Context

Planning lived in `PLAN.md` (live stages, data contract, open questions, progress log), `docs/archive/*.md` (closed stages, append-only) and `docs/architecture.md`, while `AGENTS.md` already documented a `docs/pm/` tree that did not exist. The PM init migrated them: stages 5–8 became milestones M5–M8 with one task document per plan task, sliced verbatim from the plan; `PRD.md` and `ARCHITECTURE.md` became the PM-owned reference documents; the pre-PM stage history moved from `docs/archive/` to `docs/history/` unchanged, so `docs/archive/` now holds only PM archive slices written by `pm_milestone_close`.

## Decision

Milestones: M5 = PLAN stage 5, in_progress, UI-501…UI-515; M6 = stage 6, backlog, APP-601…APP-606; M7 = stage 7, backlog, APP-701, DOC-702, DOC-702b, APP-703, APP-704, DOC-705, DOC-706, DOC-707; M8 = stage 8, backlog, DATA-801, DATA-802. Task ids keep the plan's own numbering so every task stays traceable, and no task text was enriched or rewritten — task documents carry the plan's own words, with the stage record and acceptance in the milestone README. Task prerequisites were left empty rather than invented, so the milestone task order is the priority order. `PLAN.md` and `docs/architecture.md` were deleted after their content was absorbed (recoverable at git commit d95e6ef); `docs/design/build-plan.md` was moved to `docs/history/design-build-plan.md` rather than deleted, because its incumbent diagnosis and risk register have no successor document. Task DOC-706's own wording named the plan file it was to update; it now names the generated plan record, because that file no longer exists, and `docs/architecture.md` references inside task bodies were retargeted to `ARCHITECTURE.md`. Nothing else was reworded. `PRODUCT.md`, `DESIGN.md`, `CAVEATS.md`, `docs/data-sources.md`, `docs/design/surfaces.md`, `docs/research/**` and `docs/inspiration/**` are live references and were preserved; references to the deleted paths were retargeted to the PM tree.

## Consequences

`docs/archive/` is empty until M5 closes. Owner decisions that existed only in the plan's progress log are now decision records in `docs/pm/decisions/`. Plan status, next task and staleness are generated into `docs/pm/plan.yml`; no document other than the source documents is authoritative for plan state. One known gap stays open: the frozen pre-PM history in `docs/history/*.md` still describes `PLAN.md` as the live plan, which is true of the sessions it records and wrong for a current reader; each history file now opens with a relocation note instead of being rewritten. Every live reference was retargeted: the task documents' provenance footers name the deleted plan file and its recovery commit, and `AGENTS.md`, `CAVEATS.md`, `PRODUCT.md`, `DESIGN.md`, `README.md`, `docs/design/surfaces.md`, `data/fixtures/README.md` and four source comments now point at `docs/pm/`, `docs/history/` or `ARCHITECTURE.md`. Generating the plan needed one harness fix: `.omp/lib/yaml.ts` now quotes a scalar that begins with a YAML indicator (`@`, backtick, `&`, `'`, `"`, `-`, `?`, `:`, `,`, `[`, `]`, `{`, `}`, `#`, `*`, `!`, `|`, `>`, `%`), because a backticked task title rendered unquoted and an `&`-leading value parsed as null.
