# The data-integrity tasks run off the critical path and never during the redesign

## Context
Both M8 tasks re-run `compute` and therefore change `data/derived.json`: DATA-801 refreshes the eight plan rows that fail the anchor check, DATA-802 resolves the two committed evidence URLs that return 404. M5's boundary and acceptance text pin `data/derived.json` at sha256 7425a331008fe0a1281a6d4f0bf4f350987f656cd135141a1ac69ef3f2317348 as the proof that the redesign moved no published number.

## Decision
M8 stays a backlog milestone and is never the active one while M5 is open. DATA-801 and DATA-802 run either before M5 starts or after M5 is accepted; landing either during M5 falsifies that evidence. When either lands, the new `data/derived.json` hash is re-recorded in `docs/pm/M5/README.md` and in the documents that carry the old pin in the same commit, so the next 'no published number moved' claim starts from a current pin. Neither task stops while `data/*.json` is half-refreshed: `validate`, `compute` and `data:check` all run before it ends.

## Consequences
The eight stale plan rows and the two 404 citations stay open until M5 closes, which is accepted: every plan-route figure keeps its Stage 1 price until then, and the README and the open-questions record already say so. M8 adds no route, token or page.
