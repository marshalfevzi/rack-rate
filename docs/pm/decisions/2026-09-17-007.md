# UI-502 registers IBM Plex through the Astro Fonts API, not hand-written @font-face

## Context

UI-502 migrated verbatim from the pre-PM PLAN stage 5.2. It prescribes
acquiring five latin-subset woff2 faces, committing them under
`apps/site/public/fonts/`, and declaring both IBM Plex families with hand-written
`@font-face` rules in `global.css`.

Astro 7.3.2, the pinned `@rack-rate/site` dependency, ships the stable Fonts API:
`fonts` in `astro.config.mjs`, `fontProviders` from `astro/config`, the
`<Font />` head component from `astro:assets`, and a local provider
(`fontProviders.local()`) that self-hosts files from the project tree. `astro`
depends on `unifont` and `fontace` directly, so the API adds no dependency.

Two constraints decide the shape. Invariant 9 requires `@rack-rate/site` to build
offline from committed data, which rules out the remote providers (Fontsource,
Google, NPM-with-remote): they download at build time. And Satori 0.33.4, the
social-card renderer, reads TTF, OTF and WOFF only and rejects WOFF2, which is
Astro's default `formats`; Satori also synthesises no bold, so every weight the
card asks for must exist as a committed face.

## Decision

UI-502 registers IBM Plex Sans (400, 500, 600) and IBM Plex Mono (400, 500)
as latin-subset woff2 through the Astro Fonts API with `fontProviders.local()`:
`formats: ["woff2"]`, `cssVariable: "--font-plex-sans"` and
`"--font-plex-mono"`, real fallbacks. `Base.astro` includes `<Font />` for each
family in the head, and `--font-sans` / `--font-mono` in the `@theme` block point
at those variables. Astro owns the `@font-face` rules, the preload links and the
metric-matched fallbacks; no rule is hand-written.

The committed faces live under `apps/site/src/assets/fonts/`, the local provider's
own directory, not `public/fonts/`: Astro emits hashed copies into `_astro/fonts/`,
so nothing is served from a hand-managed `/fonts/` path.

Seven faces are committed: the five woff2 a browser loads, plus
`ibm-plex-sans-latin-400-normal.woff` and `ibm-plex-sans-latin-600-normal.woff`
for Satori. `og.ts` reads those two woff files directly, maps the card's
`fontWeight: 700` onto the frozen 600 step, and stays a post-build script.

Provenance is unchanged: the OFL 1.1 text is committed beside the faces, and each
face's source URL, byte length and sha256 is recorded in `ARCHITECTURE.md`. No
remote font provider, no `public/fonts/`, no new dependency, no hand-written
`@font-face`.

## Consequences

UI-502's Scope, Files, Work and Done-when are rewritten; its status stays
`todo`, `pre` stays empty, and its acceptance criterion and migration history are
retained. The task's own ARCHITECTURE.md update now covers the font configuration
in "Design tokens" and the Satori input in "Social card"; the forward reference at
ARCHITECTURE.md line 1416–1419 stops saying "the five `@font-face` rules".

M5's acceptance line "Five committed woff2 files, zero remote font requests" still
holds, and its ban on a new dependency still holds because `unifont` and
`fontace` ship with `astro`. UI-514 (remove the Lato faces) and UI-515 (re-derive
the design record) are unaffected; no other task changes.

A later stage that needs another weight adds a variant to the `fonts` config
rather than a rule in CSS.
