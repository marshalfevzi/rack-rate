# Artificial Analysis stays out of committed data until publication is chosen explicitly

## Context

Committed Artificial Analysis rows can only exist when the fetcher is enabled with `AA_API_KEY` and `AA_PUBLISH=1`. No redistribution right has been granted: `CAVEATS.md` §1 records that the AA terms arguably make this project a restricted 'Competitive Product', and three states are defensible in ascending exposure — AA off (the default), chart-only (the AA index as its own labelled axis carrying the logo and a hyperlink, with no AA value in any data file, export, table or CSV), and AA values in `data/*.json` (the state the owner accepted on 2026-09-14). The enabled path has since been proven live, so what remains is a configuration decision rather than an engineering one. PLAN stage 7 task 7.2b owns the choice and `CAVEATS.md` §1.6 is the reader-facing statement of the position.

## Decision

AA remains disabled in committed data. It is excluded from every composite, axis, table and export unless both `AA_API_KEY` and `AA_PUBLISH=1` are set, and the deployed `/sources` page must state which state the build is in, so a reader can tell whether AA data is present because it was cleared or because a key happened to be configured. The choice between the three states is recorded at task 7.2b with its reasoning in `CAVEATS.md` §1.6; the chart-only variant stays reachable by configuration, never by a refactor.

## Consequences

`validate` fails when committed AA rows exist while `AA_PUBLISH` is not exactly `1`; the reverse case is downgraded to a loud warning. Invariants 5 and 10 hold in every state: an AA value never merges into a number that hides its origin, and the site states its state. No byte of `data/*.json` changes until 7.2b records a state.
